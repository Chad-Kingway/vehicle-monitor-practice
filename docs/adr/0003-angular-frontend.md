# 以學習 Angular 為目的遷移前端

本專案決定將監控與乘客介面由 Vanilla JavaScript 遷移至 Angular，目的是學習 Angular；目前沒有既有功能痛點，公司僅確認使用 Angular，版本與架構慣例尚不清楚，因此不以推測的公司做法作為依據。相較僅以 Angular 包裝既有 UI 接口，本次將畫面元件、HTTP 通訊與前端狀態管理納入遷移範圍，以增加實際使用 Angular 的學習內容，並接受較多的遷移與驗證工作。

既有功能與操作流程維持原樣，Python + FastAPI Server、Python 車輛 Client 與 HTTP 通訊分工維持不變，路線規劃與離線任務處理沿用既有 ADR。地圖與 3D SDK 保留專用封裝，由 Angular 銜接；遷移須保留既有的輪次核對、送單結果確認與避免重複送單行為。

前端開發與建置改由 Angular CLI 管理，保留現有 API 代理、地圖憑證設定與開發網址。Angular 通過功能驗收後，取代原版、調度台與 UI 模板入口的舊版實作，保留現有網址的相容入口；舊程式由 Git 歷史保存，不長期維護兩套前端。此決策取代 `docs/ui-interface.md` 原先要求保留原版入口與共用模組的限制，相關規範與操作文件於實作時同步更新。

整合後的介面以 main（`index.html` 原版介面）為畫面基準，保留各入口既有功能；原版、調度台與 UI 模板不再各自維護一套畫面。前端以 Angular service 與 Signals 管理狀態，以 HttpClient 與 RxJS 處理 HTTP 通訊及輪詢，不額外導入狀態管理套件。採 Angular CLI、TypeScript 與 standalone components 作為實作基礎；公司實際版本與使用慣例未確認，這些選擇不代表與公司完全相同。

地圖由持續存在的工作區外層元件持有；工作區內切換清單、接送任務、設定、詳情或其他需要同一張地圖的內容時，不銷毀地圖。離開整個地圖工作區才釋放地圖資源，實作前須依 SDK 官方文件確認釋放介面；不得假設存在未確認的 SDK 方法。監控開啟乘客頁維持原有方式，每個瀏覽器分頁持有自己的地圖。HTTP、訂閱與事件監聽依各自生命週期清理，保留地圖不代表離開的內容可持續輪詢。

依既有人工驗收文件確認監控選車與跟隨、乘客送出與取消、斷線恢復、輪次切換、地圖與各入口網址相容性，並檢查工作區內切換不會重複初始化地圖或累積輪詢及監聽。遵守專案預設不新增測試的限制；實作連續完成，不安排逐步等待使用者操作的教學流程。

本記錄整理訪談已確認的決策；完整方案待使用者確認共同理解後，才開始遷移實作。
