請求重送與去重流程

乘客端

  1. 新送出時，用 crypto.randomUUID() 建立 client_request_id。
  2. 將完整 payload 保存在 pending request 中，再發送 HTTP POST。
  3. 結果不確定時，重用保存的 payload，因此仍使用原本的 ID。

Server

  • 以 (passenger_id, client_request_id) 查詢 self.idempotency。
  • 找到舊 request：回傳原 request view。
  • 找不到：建立新 request，再記錄這個鍵對應的 request ID。

這個識別機制用來把同一次送出和它的重試連起來。乘客 ID 也在鍵裡，因此不同乘客可以各自使用相同字串的 request ID。
