# 03：每乘客單筆目前請求與操作界線

**來源規格：** [下一輪監控與乘客頁調整規格](../spec.md)

**交付行為（What to build）：** 乘客手動或隨機送出後專注一筆目前乘車請求，同身分跨分頁也只能有一筆進行中請求；終止後可提出下一筆。

**Blocked by:** 無，可立即開始。

**驗收條件：**

- [ ] 移除乘客頁「新增乘客」，保留監控頁入口與網址乘客身分；不同乘客可各自送出。
- [ ] Server 保證同乘客跨頁／併發最多一筆進行中請求，手動與隨機共用限制；進度待確認也占用名額。
- [ ] 同身分跨頁競爭收斂至 Server 已受理的請求，保留既有識別碼去重契約。
- [ ] 等待派車可取消；所有進行中狀態不得修改起訖／人數或提出下一筆，規劃開始及進度待確認不接受取消。
- [ ] 取消與派車競爭以 Server 結果為準；完成、取消、失敗後才可再送，失敗不自動建立另一筆。
- [ ] 目前請求優先為進行中，否則為最近終止結果；終止結果留至下一筆受理，乘客頁不累積列表，本輪較早紀錄仍在 Server／監控頁。
- [ ] 經 HTTP 併發與實際同身分雙分頁核對單筆限制及各狀態操作。

**覆蓋規格：** 使用者故事 16～29；人工驗收 1、5、6。
