# 08：本輪 HTTP 與網頁整合驗收

**來源規格：** [下一輪監控與乘客頁調整規格](../spec.md)

**交付行為（What to build）：** 操作者可依實際執行紀錄核對整輪功能、組合行為與剩餘驗收缺口。

**Blocked by:** [01：全車速度拉桿與續行](01-fleet-speed-slider.md)、[02：回報與網頁更新間隔永久設定](02-persistent-update-intervals.md)、[03：每乘客單筆目前請求與操作界線](03-single-current-ride-request.md)、[04：請求送出結果不明與刷新恢復](04-ride-request-recovery.md)、[05：乘客承接車位置與分段接送進度](05-passenger-trip-tracking.md)、[06：POI 切換與顯示偏好恢復](06-poi-display-preferences.md)、[07：行駛中模型比例拉桿與偏好](07-model-scale-preferences.md)

**驗收條件：**

- [ ] 執行規格全部 12 項人工情境，逐項記錄操作、可觀察結果及未通過／未執行的原因。
- [ ] 核對 0.25 秒更新下調速、單筆限制、跨頁送出、回應遺失及新輪次恢復的組合行為。
- [ ] 在實際乘客承接車地圖核對 POI、比例、鏡頭、階段路線，以及偏好同步／重載與車位更新的組合行為。
- [ ] 同輪失聯只阻斷 HTTP、保留程序；核對進度待確認仍占用名額，恢復原任務，不轉派或提前完成。
- [ ] 執行適用的現有建置、語法、依賴及差異檢查；不得以檢查成功宣稱網頁／SDK 項目通過。
- [ ] 不新增測試檔；遇到必須新增且有具體回歸風險時依專案規範先取得同意。
- [ ] 驗收記錄明確區分已實測、失敗與未執行；缺口未解決不標記任務完成，不擅自修改父規格。

**覆蓋規格：** 全部使用者故事及 12 項人工驗收，重點為跨功能整合。
