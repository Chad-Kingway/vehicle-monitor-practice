# 04：請求送出結果不明與刷新恢復

**來源規格：** [下一輪監控與乘客頁調整規格](../spec.md)

**交付行為（What to build）：** 乘客在回應遺失、刷新或連線中斷後恢復原次請求，不建立重複請求；Server 新輪次則讓乘客自行提出新需求。

**Blocked by:** [03：每乘客單筆目前請求與操作界線](03-single-current-ride-request.md)

**驗收條件：**

- [ ] 保存原次送出資料與識別碼，結果不明先核對，必要重試沿用同一識別碼；隨機請求沿用原次起訖。
- [ ] 刷新後繼續核對原次操作，結果未確認前禁止新的送出；同身分不同分頁仍收斂至同一筆受理結果。
- [ ] 首次載入及讀取 Server 失敗時停用送出／取消，重新成功讀取後恢復適當操作；已有畫面保留並標示連線中斷。
- [ ] 網頁斷線與 Server 判定車輛失聯分別呈現，不因網頁讀取失敗推斷車輛離線。
- [ ] 新輪次清除舊目前請求與未確認送出，保留乘客身分及地圖偏好，提示「模擬已重新開始」，不自動重送。
- [ ] 模擬已受理但回應遺失後刷新、隨機重試及 Server 重啟，從 HTTP 與網頁核對無重複請求。

**覆蓋規格：** 使用者故事 30～35；人工驗收 5、8、9。
