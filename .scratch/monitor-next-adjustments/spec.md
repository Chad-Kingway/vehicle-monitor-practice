# 下一輪監控與乘客頁調整規格

## 問題陳述（Problem Statement）

操作者需要在接送途中直接調整全車速度與模型大小，並更頻繁掌握狀態。目前速度使用數字輸入加套用按鈕，模型比例固定，兩種更新間隔需手動改設定檔並重啟，地圖也缺少 POI 顯示開關。

乘客提出乘車請求後，目前只能看到階段與承接車輛識別碼，無法從地圖掌握承接車位置與分段進度。頁面會累積請求，同一乘客可以建立多筆進行中請求；跨分頁、刷新或送出回應遺失時，也缺少一致的恢復流程。

下一輪需要讓監控控制更直接、設定可永久保存，並讓乘客頁集中呈現一筆目前乘車請求及其接送過程。

## 解決方案（Solution）

| 調整 | 確認內容 |
| --- | --- |
| 速度拉桿 | 全車 1～300 倍、步進 1、預設 60；拖曳調速，不重置進度 |
| 回報與更新 | 各預設 0.25 秒；監控頁永久保存，下一次成功通訊後生效 |
| 乘客入口 | 乘客頁移除新增入口，監控頁保留 |
| 目前請求 | 每乘客最多一筆進行中；承接車位置、分段進度、跨頁與刷新恢復 |
| POI | 所有地圖右上角切換，預設顯示，按頁面類型保存偏好 |
| 模型比例 | 本頁全車 1～100、步進 1、初始 30；行駛中可調，成功後保存偏好 |

乘客頁在請求結束後保留最後一筆結果，直到下一筆受理。更早紀錄仍留在 Server 與監控頁，依原規格保留至 Server 重啟；乘客頁不累積歷史列表。

## 使用者故事（User Stories）

## 實作決策（Implementation Decisions）

### 模組與介面

- 維持既有 Server／Client 架構與 HTTP 通訊，延伸全域設定管理與保存介面、乘車請求受理與查詢、乘客頁恢復、共用網頁更新、共用地圖顯示及監控控制；優先使用既有接點。
- Server 保證跨頁單筆限制，受理流程沿用乘客身分與 `client_request_id` 去重；重試須恢復原次結果，不能因重試或限制建立另一筆請求。
- 乘客頁使用既有乘車請求、接送任務與承接車關聯，讀取最後回報位置、路線及分段進度，不另建司機模型。

### 監控控制與永久設定

- 監控頁速度控制改為滑動拉桿，全車共用，範圍 1～300 倍、步進 1、預設 60 倍，執行中調整不重置車位、路線、任務或進度。
- 拖曳時調速，不另按套用；最多每 0.25 秒送出一次，放開時送出最終值。車輛於下一次成功通訊後採用。
- 速度修改只對目前模擬有效，不永久保存，Server 重啟回設定檔預設值；本輪預設改為 60。更新失敗時顯示簡短錯誤及 Server 已確認的值。
- 車輛回報與網頁更新維持兩個獨立的全域設定，預設各 0.25 秒。
- 監控頁以兩個可直接填秒數的數字欄位與一個「儲存設定」按鈕修改間隔，寫入既有共用設定檔。
- 間隔範圍 0.1～60 秒、步進 0.05 秒；車輛回報間隔另須嚴格小於目前離線門檻（現為 10 秒）。不符合時顯示原因並拒絕保存，不連帶修改離線門檻。
- 網頁永久保存的 Server 設定限於這兩種間隔，保留設定檔其餘項目。
- 儲存成功後立即更新 Server 設定，車輛與所有開啟的網頁於下一次成功通訊後採用，不重置模擬，重啟後保留。
- 保存失敗維持原設定；多個監控頁修改以最後成功保存的設定為準。
- 網頁更新設定套用所有現有網頁，包含監控與乘客兩種網頁；車輛 Client 為 Python 程序。

### 乘客頁

- 移除乘客頁「新增乘客」入口，保留監控頁建立或開啟不同乘客身分的入口。
- 同一乘客身分最多一筆尚未結束的乘車請求，由 Server 保證限制。
- 同身分的不同分頁顯示同一筆請求，不能各自建立另一筆進行中請求；不同乘客可分別提出請求。
- 進度待確認仍占用單筆名額。
- 等待派車可以取消，不能修改起訖與人數，不能提出下一筆。
- 規劃路線、前往接人、載客行駛及進度待確認均不能取消、修改起訖與人數或提出下一筆。
- 完成、取消及失敗後可以準備並提出下一筆；失敗不自動建立另一筆。
- 取消與派車競爭時以 Server 結果為準。
- 送出結果不明時保存原次資料與識別碼，先恢復原次結果；需要重試時沿用同一識別碼，隨機請求沿用原起訖。刷新後繼續核對，確認前停用送出。
- 同身分跨頁送出競爭時，顯示 Server 已受理的那一筆。
- 初次載入與網頁讀取 Server 失敗時，停用送出及取消，直到重新讀取成功。已有位置及進度時保留最後畫面，標示「連線中斷」；車輛失聯依 Server 判定，網頁恢復後繼續原請求。
- Server 新輪次清除舊輪次的目前請求及未確認送出，保留乘客身分與地圖偏好，提示「模擬已重新開始」，不自動重送舊請求。
- 顯示承接車輛位置，不新增司機資料模型。
- 進度採接送階段與該階段百分比；前往接人與載客行駛分段計算。
- 百分比沿用車輛 Client 回報，不另建整趟算法。等待派車、規劃路線只顯示階段，完成顯示已送達；失聯保留最後位置與百分比，標示「進度待確認」與最後回報時間，不推估後續進度。
- 乘客頁只專注一筆目前乘車請求。結束後保留最後一筆結果至下一筆受理，更早紀錄保留於 Server／監控頁，乘客頁不累積列表。
- 地圖只顯示承接車輛、目前請求的起訖標記與目前階段路線；接人時顯示接人路線，載客時改為送人路線。
- 首次取得路線調整鏡頭，其後保留手動操作，提供定位承接車按鈕；結束後停止追蹤車輛，保留起訖及最後路線至下一筆受理。

### 地圖顯示偏好

- 所有有地圖的頁面提供右上角 POI 按鈕，切換 `poi_` 圖層圖標與名稱。
- POI 預設顯示，偏好於同一瀏覽器保存，刷新後維持。
- 模型比例拉桿控制目前頁面顯示的所有車輛，行駛中可以調整，各頁面偏好在同一瀏覽器保存。
- 模型比例範圍 1～100、步進 1，未保存偏好時初始比例為 30。拖曳立即套用，成功後保存偏好；之後出現的車輛模型使用目前比例。
- POI 與模型比例按監控頁／乘客頁兩種頁面類型分別保存，不按乘客身分區分；同瀏覽器的所有乘客頁共用乘客頁偏好，同類型分頁同步修改，樣式重載後重套。這兩項偏好不寫入 Server 設定檔。
- POI／模型比例只有套用成功後才保存新偏好。套用失敗嘗試還原並顯示簡短錯誤；還原也失敗則暫停該控制，待地圖重新載入後恢復。
- 若僅瀏覽器無法保存，允許本頁繼續使用已套用的選擇，提示「偏好未保存」。

### 相容範圍

- 維持 Vite＋Vanilla JavaScript 前端、Python＋FastAPI 後端與 HTTP 通訊。Server 管理車輛、乘車請求與接送任務；車輛 Client 模擬並回報，乘客 Client 提出請求，監控網頁呈現 Server 資料。
- 路線仍由 Server 統一規劃，地圖與 3D 模型留在前端；既有單一 worker 及第三方路線查詢併發控制沿用。
- 取消界線與離線任務保留沿用既有領域決策。未載客失聯暫停、已載客依快取續行，Server 保留原任務與進度待確認，恢復時核對原任務。永久失聯仍由操作者重新開始整場模擬，不增加自動轉派或乘客放棄已執行任務的操作。
- 各種間隔及離線門檻按真實時間計算，不受速度倍率影響。
- Server 歷史資料仍為本輪記憶體資料，重啟開始新一輪；本輪的永久保存限於兩種間隔及瀏覽器地圖偏好。
- 頁面文字保持精簡；必要狀態與錯誤提示依上述規則呈現。

## 測試決策（Testing Decisions）

### 驗證接點與既有作法

- 好的驗證核對外部可觀察行為：HTTP 受理結果、跨 Client／分頁的一致狀態、設定重啟保存，以及實際頁面的控制、地圖與提示；不以內部函式呼叫或實作相似的檢查取代驗收。
- 沿用使用者已於 Q23 確認的 12 項人工驗收情境；驗證接點使用現有 HTTP 與實際網頁，不新增接點。全域設定及單筆限制在 HTTP 層核對，地圖與瀏覽器偏好在網頁核對；跨頁、刷新與回應遺失須同時核對兩者。
- 覆蓋全域設定保存、乘車請求受理與恢復、車輛調速續行、網頁更新、乘客地圖及顯示偏好。SDK 可見效果需在實際瀏覽器驗收。
- 既有第一版整合驗收使用真實 Server／車輛 Client 的即席 HTTP 驗證與人工網頁驗收；現有診斷開關能只阻斷車輛 HTTP、保留程序驗證同輪失聯及恢復。已有報告中的未完成瀏覽器項目仍是驗收缺口。
- 目前沒有既有自動測試，依專案規範預設不新增測試檔。未來若能指出具體回歸風險而需新增，須先取得同意；實作時執行適用的建置、語法與依賴檢查，不能以此替代網頁／SDK 驗收。

### 人工驗收情境

以下為功能實作後的驗收情境，目前僅完成文件核對。

1. 清除地圖偏好後啟動，確認速度預設 60、兩種間隔各 0.25 秒、模型比例 30、POI 顯示；乘客頁無新增入口，監控頁可開啟不同乘客。
2. 車輛接送途中拖曳速度拉桿，確認 1～300 整數倍率、放開後採用最終值，車位與任務進度持續；Server 重啟後回預設 60。
3. 監控頁保存合法間隔，確認檔案保存且各車輛及監控／乘客網頁在下一次成功通訊後採用；重啟後保留，設定檔其他項目不受更動。
4. 輸入超出範圍或不小於離線門檻的回報間隔，確認拒絕保存並維持原設定；讓設定檔無法寫入，確認失敗提示及原設定維持。開兩個監控頁修改，以最後成功保存為準。
5. 同一乘客開兩個分頁，同時手動或隨機送出，確認只有一筆進行中請求，兩頁收斂顯示同一筆；不同乘客可分別送出。
6. 依序核對等待、規劃、接人、載客、進度待確認、完成、取消及失敗的操作界線；等待取消與派車競爭以 Server 結果為準，終止後才可提出下一筆。
7. 核對承接車位置、當前階段路線、起訖、分段百分比及定位按鈕；手動調整鏡頭後輪詢不搶回鏡頭，結束後停止追蹤，下一筆受理前保留結果。
8. 保持 Server／車輛 Client 程序存活，僅阻斷 HTTP，確認車輛進度待確認保留最後回報，網頁連線中斷停用操作；恢復後續行原請求。直接重啟 Server 則須清除舊輪次，不自動重送。
9. 模擬乘客送出已到 Server 但回應遺失，再刷新並恢復，確認沿用原次識別碼及資料、不重複建立請求；隨機請求不得重新抽起訖。首次載入讀取完成前送出與取消停用。
10. 多車行駛中拖曳模型比例，核對 1～100 整數比例與位置持續更新，後續模型繼承目前比例；切換 POI 確認目標樣式的圖標與名稱均切換。
11. 修改兩種地圖偏好後刷新、開啟其他乘客身分與重載樣式，確認按頁面類型保存／同步並重套，監控與乘客偏好互相獨立。
12. 模擬 POI／比例套用失敗、還原失敗及瀏覽器保存失敗，核對還原、控制暫停、重載恢復與「偏好未保存」提示。

## 範圍外（Out of Scope）

- 本次直接實作應用程式、拆分實作任務或新增測試檔；本次交付為需求規格發布。
- 新增車輛網頁、司機資料模型、正式乘客登入或對外營運身分管理。
- 共乘、同車多任務、忙碌車輛後續預約，或同乘客同時建立多筆進行中請求。
- 規劃開始後取消、進度待確認時放行下一筆、永久失聯自動轉派。
- 整趟百分比、失聯時推估位置／進度、額外上下客等待時間或自動返回初始位置。
- Server 請求／任務歷史持久化、重啟恢復舊輪次，以及乘客頁累積歷史列表。
- 永久保存速度修改，或從網頁修改兩種間隔以外的 Server 設定；比例與 POI 為瀏覽器顯示偏好。
- 上百台車效能保證、負載驗證、多 worker／共享儲存架構與第三方服務配額保證。
- 修改、刪除或提交舊專案，以及將模型檔納入 Git。

### 現況與規格差異

- 既有速度預設 10，Server 接受大於 0 且不超過 300 的倍率，監控為數字輸入與套用按鈕、速度只保存在記憶體。本輪改為預設 60 與 1～300 整數拉桿。
- 兩種間隔目前各預設 1 秒，手動改設定檔並重啟生效，沒有網頁保存端點。本輪改預設 0.25 秒，提供執行中永久保存並生效，取代原規格對這兩項的重啟限制；其餘 Server 設定仍沿用原規格。
- 乘客身分來自 URL 的 `passenger` 參數。既有流程為 waiting、planning、pickup、transport、completed，另有 cancelled、failed，只有 waiting 可取消；進度待確認保留原任務及階段。
- Server 已有乘客與 `client_request_id` 去重，但瀏覽器未保存送出意圖；本輪補齊恢復。既有資料已包含任務分段進度、路線與承接車位置，乘客頁尚未使用；本輪集中呈現這些資料。
- Server 歷史仍為記憶體資料至重啟，不另行持久化。舊 POI 刷新不保存；舊比例為數字輸入與套用且行駛中禁止，本輪是新增拉桿、行駛中可調及偏好保存。

### 官方依據與實作驗證

- 官方 [onLayer](https://kw3dmap.localking.com.tw/3dmap/api/map/methods#onlayer)、[offLayer](https://kw3dmap.localking.com.tw/3dmap/api/map/methods#offlayer) 以圖層 id「包含」字串切換，[redraw](https://kw3dmap.localking.com.tw/3dmap/api/map/methods#redraw) 可同步重繪；已在需求訪談核對。目標樣式的 `poi_` 是否完整涵蓋圖標／名稱仍須實際驗證。
- 官方 [setScale](https://kw3dmap.localking.com.tw/3dmap/api/mapThree/model#setscale) 以模型建立時比例為基準。文件未限制行駛中調整，也未保證連續位置／朝向更新與多模型縮放效果，實作必須完成對應驗收。
- 舊專案只供唯讀參考，不以其使用方式宣稱 SDK 行駛中縮放或目前樣式 POI 已實測通過。
