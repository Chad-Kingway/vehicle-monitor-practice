# 下一輪監控與乘客頁調整

本文件記錄需求訪談；功能尚未實作，待所有分支釐清並確認共同理解後發布完整規格。
上一輪基準為 [車輛監控規格](../vehicle-monitor/spec.md)。

## 已確認需求

### 監控控制與永久設定

- 監控頁速度控制改為滑動拉桿，保留執行中調速及不重置進度的要求；範圍、步進與送出時機待確認。
- 車輛回報與網頁更新維持兩個獨立的全域設定，預設各 0.25 秒。
- 監控頁提供兩種間隔的修改與永久保存入口，寫入既有 `config/simulation.json`；生效時機待確認。
- 網頁更新設定套用所有現有網頁。程式查核顯示目前只有監控與乘客兩種網頁，車輛 Client 為 Python 程序；不因第一輪提及車輛頁而新增頁面。

### 乘客頁

- 移除乘客頁「新增乘客」入口，保留監控頁建立或開啟不同乘客身分的入口。
- 同一乘客身分最多一筆尚未結束的乘車請求，由 Server 保證限制。
- 同身分的不同分頁顯示同一筆請求，不能各自建立另一筆進行中請求；不同乘客可分別提出請求。
- 進度待確認仍占用單筆名額。
- 顯示承接車輛位置，不新增司機資料模型。
- 進度採接送階段與該階段百分比；前往接人與載客行駛分段計算。
- 乘客頁只專注一筆目前乘車請求。結束後保留最後一筆結果至提出下一筆，更早紀錄保留於 Server／監控頁，乘客頁不累積列表。

### 地圖顯示偏好

- 所有有地圖的頁面提供右上角 POI 按鈕，切換 `poi_` 圖層圖標與名稱。
- POI 預設顯示，各頁面開關偏好在同一瀏覽器保存，刷新後維持。
- 模型比例拉桿控制目前頁面顯示的所有車輛，行駛中可以調整，各頁面偏好在同一瀏覽器保存。
- 第一輪原建議初始比例 10，使用者回答「是，但初始可以拉到 30」；預設值與上限含義尚未確認。

## 現況查核與原規格差異

- 既有速度預設 10，Server 接受大於 0 且不超過 300 的倍率；監控目前為數字輸入與套用按鈕，速度更新只保存在記憶體。
- 兩種間隔目前預設 1 秒，手動編輯設定檔並重啟 Server 生效，尚無網頁保存端點。本輪已確認更換預設值與新增設定入口；執行中生效仍待決策。
- 原規格將速度之外設定的執行中調整列為範圍外；若後續選擇即時生效，本輪規格須明確取代該限制。
- 乘客身分取自 URL 的 `passenger` 參數，刷新、複製網址或分頁沿用相同身分。
- 既有流程為 waiting、planning、pickup、transport、completed，另有 cancelled、failed。只有 waiting 可取消；進度待確認保留原任務與階段。
- Server 已依乘客與 `client_request_id` 去重，但瀏覽器未保存送出意圖，回應中斷後重送可能建立另一筆請求。
- 既有任務資料包含分段進度、路線與承接車輛最後回報位置；乘客頁尚未使用車輛與任務資料。
- 歷史目前保留於 Server 記憶體至重啟，不持久化；本輪尚未要求改變此生命週期。
- 舊專案 POI 有樣式重載重套與失敗還原，刷新不保存；模型比例為數字输入、全車套用、行駛中禁止。新需求不能直接視為原樣移植。
- 舊專案只供唯讀參考。POI 與模型調整的第三方 SDK 介面仍須在實作前依官方文件確認，並驗證行駛中及多模型行為。

## 待釐清分支

- 兩種間隔：生效時機、範圍與步進、保存失敗、跨監控頁修改。
- 速度拉桿：範圍與步進、拖曳送出、保存範圍、連線失敗。
- 模型比例：初始 30 的含義、範圍與步進、套用時機與失敗。
- 乘客操作：各狀態的取消、編輯與下一筆入口，送出與取消競爭。
- 恢復：初次載入、刷新、送出結果不明、跨頁同時送出、Server 新輪次。
- 進度：計算依據、等待與規劃、失聯與送達呈現。
- 地圖：承接車、路線、標記、鏡頭與結束後呈現。
- 偏好：頁面類型或身分的保存單位、同類分頁同步、樣式重載與套用失敗。
- 訪談結束後確認共同理解，再決定完整規格與是否拆分實作任務。
