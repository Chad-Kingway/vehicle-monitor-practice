# 乘客重複叫車與跟隨承接車

## 問題

監控頁沒有直接以隨機乘客提出一筆請求的入口。乘客頁雖可在前一筆終止後重新選點，但成功輪詢會把選點覆寫成上一筆起訖。乘客頁只有一次性定位承接車的操作，無法持續查看車輛移動。

## 已確認方案

1. 監控頁新增「隨機送出一筆」入口。按下後另開一個新乘客頁，由該頁立即提出一筆隨機請求並顯示進度。乘客頁既有隨機送單功能維持不變。
2. 乘客地圖沿用 Server 接送任務的道路路線；前往接人顯示接人路線，載客顯示送人路線，不在乘客頁自行計算路線。現有資料流已符合此行為。
3. 每位乘客仍最多只有一筆進行中的乘車請求。前一筆完成、取消或失敗後才可重新選點及送出。輪詢期間保留新選點；新請求受理後以該請求的 Server 指派車輛更新車位及地圖。
4. 將乘客頁一次性「定位承接車」改為可切換的「跟隨承接車」。開啟時持續跟隨目前請求的承接車；乘客可手動關閉，請求結束時自動停止。

## 驗收方式

- 從監控頁按「隨機送出一筆」，確認另開的新乘客頁有新的乘客身分、自動只送出一筆隨機請求，且能看到該請求；在乘客頁手動使用既有隨機按鈕仍可送單。
- 請求接人時確認乘客地圖顯示 Server 接人道路路線，開始載客後切換到 Server 送人道路路線。
- 完成、取消或失敗一筆請求後重選起訖，等待多次網頁輪詢，確認選點不變；送出後以新請求的 `vehicle_id` 核對車輛位置及地圖車輛。
- 開啟「跟隨承接車」，確認車輛回報位置更新時鏡頭持續跟隨；手動關閉後鏡頭不再追蹤，請求終止時跟隨自動關閉。

## 實作說明

- 新增的監控入口以 URL 啟動旗標請乘客頁在首次成功讀取 Server 後送出，沿用既有 `client_request_id`、送出暫存及恢復流程。
- 不新增詞彙或架構決策；沿用既有乘車請求、接送任務、Server 派車及地圖跟隨模型。
