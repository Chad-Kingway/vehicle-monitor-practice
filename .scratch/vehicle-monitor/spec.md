# 車輛監控系統規格

Status: draft

## 既定規範

- 前端使用 Vite + Vanilla JavaScript（HTML / CSS），後端使用 Python + FastAPI，通訊統一使用 HTTP。
- Server 管理車輛、需求與任務資料；車輛 Client 負責模擬及回報狀態；乘客 Client 負責提出需求；監控網頁負責顯示 Server 資料。
- 地圖與 3D 模型顯示留在前端；第三方 SDK / API 須以官方文件確認。
- `../kwmap-practice/` 僅供讀取與參考；所有修改限於本專案。

## 已確認需求

- 乘車請求包含上車點、下車點與乘車人數。
- 第一版以同一台電腦執行 Server、車輛 Client、乘客 Client 與監控網頁，完成模擬展示。
- 使用模擬車輛與乘客資料。
- Server 使用記憶體保存資料；重啟後清空車輛狀態、需求與任務，重新開始模擬。
- 乘客送出乘車請求後，由 Server 自動派車；有空閒車輛時指派，否則等待。
- 一個接送任務由一台車執行一筆乘車請求，包含前往上車點、接人與送達下車點；每台車同時只執行一個任務。
- 第一版不安排共乘，也不讓車輛同時承接多筆乘車請求。
- 車輛 Client 使用獨立 Python 程式模擬行駛並透過 HTTP 回報；關閉監控網頁不影響模擬執行。
- 地圖與車輛 3D 模型沿用舊專案；SDK / API 整合仍須依官方文件確認。
- 將舊專案車輛模型複製至本專案 `public/models/car/`，並以 `.gitignore` 排除 `public/models/`，不納入 Git 追蹤。
- 第一版先處理最早送出的等待請求，再從符合條件的空閒車輛中，以到上車點的直線距離選擇最近的一台；實際行駛路線另外規劃。
- 每台車有載客上限，只能承接人數未超過上限的乘車請求；超過整個車隊最大載客上限的請求直接拒絕。若合適車輛忙碌，請求繼續等待。
- 車隊預設三台車，可透過設定調整數量。
- 乘客 Client 使用獨立網頁，供乘客送出乘車請求並查看自己的請求狀態。
- 系統另須支援隨機時間自動生成乘車請求；自動生成由哪個角色與程式啟停尚待確認。
- 乘客網頁提供一鍵產生並送出一筆隨機乘車請求，由 Server 依派車規則處理。

## 後續演算法需求

使用者提出未來可能比較空閒車輛執行新任務的完成時間，以及忙碌車輛完成現有任務後再執行新任務的完成時間，選擇較快方案。

第一版先維持只指派空閒車輛，將選車邏輯集中在可替換的派車模組；忙碌車輛的後續任務預約與時間比較留到下一階段。

## 尚待釐清

各車載客上限與初始位置、自動生成請求的控制角色與生成規則、道路路線取得方式與併發處理、狀態轉換、回報與異常處理、監控操作及驗收情境尚未確認；本文件仍在討論中。
