Vehicle Monitor · Lesson 20

Angular track 完整教學

從一列資料如何對應一列畫面，到 HTTP 更新、排序與錯誤識別值。

track 指定每個項目的識別值，讓 Angular 在清單更新時對應既有畫面列。畫面列包含 HTML 元素；若列中有子元件，也包含子元件實例。這種對應決定哪些內容可以沿用、移動、建立或移除。

閱讀順序：語法 → 更新推演 → 識別值選擇 → 常見錯誤 → 練習與解答。

1. 語法：track 後面是運算式

@for (vehicle of fleet(); track vehicle.id) {
  <button>{{ vehicle.id }}</button>
}
  • fleet()：取得這次要顯示的清單。
  • vehicle：每一輪拿到的車輛。
  • track vehicle.id：以這台車的 ID 辨認它所對應的畫面列。
  • 大括號內是每一列的範本。

這是 Angular 範本語法，track 不是 TypeScript 的一般迴圈關鍵字，也不是 HTML attribute。@for 需要寫 tracking expression，不能只刪掉 track vehicle.id。參考 @for API。

2. Angular 更新時做什麼？

第一次沒有舊畫面可比，Angular 建立各列。下一次清單更新，再依識別值對應。用字母表示既有畫面列：

舊資料 ID          01       02       03
既有畫面列         A        B        C

新資料 ID          03       01       04
對應畫面列         C        A        D（新建）

B 對應的 02 不在新清單中 → 移除

03、01 可沿用各自的畫面列並調整位置；04 新增一列；02 移除。順序由新清單決定，track 負責辨認身分。

如果 ID 不變，車輛位置等資料改變，Angular 仍更新那列的文字、屬性或元件輸入。沿用畫面不代表忽略新資料，也不代表停止計算。

3. 為什麼會影響使用者？

畫面元素除了文字，也可能有鍵盤焦點、文字選取或輸入狀態；列裡的元件也可能保存自己的展開狀態。正確對應讓這些狀態能繼續跟著同一筆資料，減少不必要的重建。若某列真的被移除，該列的狀態也不會靠 track 永久保存。官方 NG0956 說明整份清單重建的成本與狀態流失問題。

4. 新的 JavaScript 物件，仍可代表同一台車

const previous = { id: 'vehicle-01', heading: 0 };
const next = { id: 'vehicle-01', heading: 90 };

previous === next       // false：不同物件
previous.id === next.id // true：同一車輛 ID

HTTP 回應解析出的物件通常是新物件。因此用 track vehicle.id，Angular 可以依穩定 ID 對應前後資料，而不是因每次物件都不同就把整份清單當成新項目。本專案的車隊 HTTP 輪詢很適合這種方式。

5. 三種常見寫法怎麼選？

track vehicle.id：追蹤資料身分。適合有新增、刪除、搜尋或排序的車隊清單。同一台車在這個清單裡應有唯一且穩定的 ID。

track $index：追蹤位置。$index 是第幾列，從 0 開始。適合固定且不會改變項目與順序的清單。如果第一列原本是 01，刪掉 01 後變成 02，Angular 會把位置 0 的畫面列沿用給 02；列內自己的狀態就可能跟著位置走，沒有跟著車輛走。

track vehicle：追蹤物件參考。適合項目物件確實保持相同參考的情況。HTTP 每次重建物件時，同 ID 也不再是同一個物件，可能導致大量重建。應優先採用明確 ID。官方選擇建議見 Control flow。

6. 常見錯誤與界線

  • track vehicle.connection_status：多台車可能都是 online，識別值重複。唯一性要求在同一份清單內，不需要和整個網站的其他清單互不重複。見 NG0955。
  • track 車輛經緯度：位置會變，兩台車也可能同位置，無法穩定代表身分。
  • 每次產生亂數或 UUID：追蹤時重新產生的值不穩定。應在資料建立時就取得 ID，後續沿用。
  • 以為 ID 相同就不更新內容：相同 ID 只代表可以對應原列；新的資料仍會更新範本繫結。
  • 以為 key 變就一定銷毀元件：現代 @for 優先沿用畫面；如果仍是同一個物件參考，即使追蹤屬性改變也可能沿用。不要以改 key 當作強制重建機制。
  • 以為 track 會送 HTTP 或偵測任意資料改動：它處理清單更新時的畫面對應；取得資料及通知 Angular 更新仍由服務、Signals 等流程負責。

7. 套回本專案

MonitorComponent 的車隊使用 track vehicle.id，接送任務使用 track task.id。車輛即使換了位置、朝向或任務，仍是相同車輛；任務則使用自己的任務 ID。搜尋讓車輛暫時離開顯示清單時，那列會移除；之後再出現會重新建立，track 不是隱藏列的快取。

8. 練習：先判斷，再展開解答

題一：前後資料都是全新的物件，ID 從 [01, 02, 03] 變成 [03, 01, 04]，使用 track vehicle.id。哪些列沿用、哪列移除、哪列新增？

展開解答

03、01 沿用並依新清單排列；02 移除；04 新增。即使物件參考全換了，也能用相同 ID 對應。

題二：每列元件用自己的欄位保存「已展開」。使用 track $index，刪掉第一台車後，原第一列的展開狀態會跟著車輛身分，還是跟著位置？車隊應改用什麼？

展開解答

會跟著位置；位置 0 的元件可能沿用給下一台車。這個車隊清單應使用 track vehicle.id，讓畫面列對應車輛身分。

題三：使用 track vehicle.id，ID 相同但 heading 從 0 變成 90。為什麼畫面可以更新朝向，又不用重新建立整列？

展開解答

ID 用來對應舊畫面列，heading 用來更新該列內容。辨認身分與更新內容是兩件事。
