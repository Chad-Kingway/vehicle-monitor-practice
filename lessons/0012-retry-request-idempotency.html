重送請求時如何避免重複建立？

追蹤乘客端的 client_request_id 如何讓 Server 認出同一筆送出。

乘客端先為這次送出建立識別碼

send() 建立 payload 時會產生 client_request_id，並把包含此 ID 的待送資料保存起來：

const payload = {
  passenger_id: passengerId,
  run_id: runId,
  client_request_id: crypto.randomUUID(),
  ...(isRandom ? {} : { pickup, destination, passenger_count: Number(count.value) })
};
const pending = { run_id: runId, endpoint: isRandom ? "/api/requests/random" : "/api/requests", payload };
storePending(pending);

如果送出結果不確定，前端之後重送保存的 payload，因此沿用同一個 ID。它不會把這次重試當成一筆全新的操作。

Server 用乘客與請求 ID 查找舊結果

Simulation.submission_identity() 將 (passenger_id, client_request_id) 當作查找鍵。若 self.idempotency 已記錄這個鍵，就取出原本的 request，submit() 直接回傳該 request view，不再建立第二筆。

key = (data.passenger_id, data.client_request_id)
existing_id = self.idempotency.get(key)
existing = self.request_view(self.requests[existing_id]) if existing_id else None

# submit() 裡
return existing if existing is not None else self.create_request_locked(data, key)

第一次成功建立請求時，Server 會把識別鍵記到 self.idempotency，並連到新 request 的 ID。這樣即使第一次回應在網路途中遺失，使用相同 payload 重送時仍能取回原結果。

辨認重試：相同乘客 + 相同 client_request_id → 回傳原請求；不同 ID → 視為新的送出嘗試。

crypto.randomUUID() 產生 UUID 字串；這裡用它為每次新的乘車送出建立識別碼。MDN 說明 randomUUID() 會產生 v4 UUID。
