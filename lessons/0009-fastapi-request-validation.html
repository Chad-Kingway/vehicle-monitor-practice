FastAPI 如何驗證收到的資料？

從 API 參數的型別追到 schemas.py 的規則。

路由參數標示資料模型

server/app.py 裡的建立乘車請求路由長這樣：

@app.post('/api/requests')
async def submit_request(data: RideRequestInput):
    return await app.state.simulation.submit(data)

data: RideRequestInput 不只是型別提示。FastAPI 會把 HTTP request body 的 JSON 讀出來，依 RideRequestInput 解析與驗證，通過後才呼叫 submit_request。模型不符合規則時，handler 不會開始執行。

模型描述欄位與限制

server/schemas.py 定義它：

class RideRequestInput(BaseModel):
    model_config = ConfigDict(extra='forbid')
    passenger_id: Identity
    pickup: Position
    destination: Position
    passenger_count: int = Field(ge=1, strict=True)
  • passenger_id、pickup、destination 和 passenger_count 都沒有預設值，所以都是必要欄位。
  • passenger_count 必須是整數，且至少為 1；strict=True 表示不把字串 "2" 自動轉成整數。
  • extra='forbid' 表示拒絕模型未宣告的多餘欄位。

pickup 和 destination 的型別是 Position，它又由經度、緯度規則組成。這就是為什麼欄位限制可以分層重用。

資料流：HTTP JSON → FastAPI 讀取 body → Pydantic 依模型驗證 → 建立 RideRequestInput → 呼叫 submit_request(data)。

小練習

如果乘車請求少了 passenger_count，或把人數傳成 0，程式會進入 submit_request 嗎？簡單說明原因。

提示：檢查欄位有沒有預設值，以及 Field(ge=1) 的意思。
