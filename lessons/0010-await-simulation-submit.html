await 如何把請求交給 Simulation？

從已驗證的資料追到路由回傳結果。

從 handler 接上 Simulation

server/app.py 的路由是：

@app.post('/api/requests')
async def submit_request(data: RideRequestInput):
    return await app.state.simulation.submit(data)

FastAPI 已先把 JSON 驗證成 RideRequestInput，再把這個物件放進 data。路由把同一個物件傳給 Simulation.submit(data)。

await 讓程式等到非同步方法完成

submit 是用 async def 定義的方法。呼叫它會得到一個尚未完成的 coroutine；加上 await 後，非同步方法才會執行。方法完成時，路由取得它回傳的乘車請求資料，再把結果交回 FastAPI 作為 HTTP response。

讀這行的順序：data 傳入 Simulation.submit → await 等待處理完成 → return 把處理結果交回 FastAPI。

如果只寫 return app.state.simulation.submit(data)，回傳的會是 coroutine 物件，而不是已處理好的請求資料。Python 官方文件也說，單純呼叫 coroutine function 不會讓 coroutine 執行；必須等待它，或用 task 排程。

下一步可看 submit 裡的 async with self.lock：它讓共享模擬狀態的檢查與修改不會被並行請求交錯。
