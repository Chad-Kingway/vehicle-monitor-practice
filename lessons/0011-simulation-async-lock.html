Simulation 怎麼保護共享狀態？

讀懂 async with self.lock，看多個請求如何共用同一把鎖。

Simulation 只建立一把鎖

Simulation.__init__ 建立 self.lock = asyncio.Lock()。這把鎖和 self.requests、self.tasks 等資料放在同一個 Simulation 物件上，所以呼叫它不同方法時會使用同一把鎖。

async with 圈出一段獨佔區域

async def submit(self, data):
    async with self.lock:
        key, existing = self.submission_identity(data)
        return existing if existing is not None else self.create_request_locked(data, key)

進入區塊前，這個 coroutine 要先取得鎖。如果另一個 coroutine 正持有同一把鎖，它會在這裡等待；鎖釋放後才進入區塊。使用同一把鎖的狀態修改方法會依序進入，不會同時處於這段受保護的區域。

離開區塊時，鎖會自動釋放；即使區塊裡提前 return 或發生例外，也會釋放。async with 把取得與釋放鎖的流程包在一起，避免忘記清理。

在這個方法裡：先檢查是否已處理過相同請求，再決定回傳現有結果或建立新請求。這些步驟都放在共享的鎖保護範圍內。

asyncio.Lock 是協調 asyncio tasks 的鎖，不是給作業系統執行緒使用的鎖。Python 官方文件說明，它用來保證共享資源的獨佔存取，建議透過 async with 使用。
